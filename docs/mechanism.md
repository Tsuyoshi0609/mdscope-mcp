# 仕組み

「見せて」から画面に 3D ビューアが出るまでに何が起きるか。設定方法は [setup.md](setup.md)、
頼み方は [usage.md](usage.md)。

## 全体の流れ

```
チャット（Claude Code / Codex / ChatGPT デスクトップ）
  └─ MCP (stdio) ─▶ mdscope-mcp（データのあるマシン）
                      ├─ MDAnalysis で読む → 選択 → フレーム抽出 → PBC 補正 → int16 化
                      ├─ ~/.cache/mdscope/view_<id>.html（3Dmol.js 同梱、自己完結）を書く
                      └─ ツール結果: 要約（LLM 向け）+ 座標（_meta、LLM には見えない）
ホストが MCP Apps 対応 → 会話内に ui://mdscope/viewer/v6.html を描画（ChatGPT / Codex デスクトップ）
ホストが Artifact 対応   → HTML を Artifact として公開（Claude Code）
それ以外                → `mdscope-mcp --serve` の URL か HTML のパスをブラウザで開く
```

座標は LLM のコンテキストに入らない。LLM が受け取るのは原子数・残基数・フレーム数・ファイルパス・警告だけ。

## ペイロード（ブラウザに渡すもの）

| 項目 | 中身 | 理由 |
|---|---|---|
| `pdb` | 選択原子だけの PDB 文字列（最初のフレーム、処理後の座標） | 3Dmol.js が結合・二次構造を決めるのに使う |
| `coords_b64` | `int16` の座標 `(フレーム, 原子, xyz)` を little-endian で base64 化 | `float32` の半分。0.01 Å 単位で表示には十分 |
| `coord_scale` | 1 単位の Å（既定 0.01。系が 320 Å を超えると自動で粗くなる） | `int16` の範囲 ±32767 に収める |
| `frame_indices` / `times_ps` | 元の軌道でのフレーム番号と時刻 | スライダーの表示用 |
| 表示設定 | `style`, `color`, `layers`, `notes` | ビューアのメニュー初期値と注記 |
| `base_serials` / `layer_serials` / `highlight_serials` / `label_serials` | 部分ごとの原子の通し番号（PDB 内の 1 始まり） | 選択文字列はサーバー側（MDAnalysis）で評価し、ブラウザには原子の番号だけを渡す |

ペイロードはツール結果の `_meta` に載せ、`view_<id>.json` としても保存する。会話内ビューアは、受け取った
ペイロードの原子数・座標の長さが合わなければ（Codex は長いツール結果の両端 約 32 KB ずつしか渡さない）、
`get_view_payload` で 24000 文字ずつ取り直す。

座標の予算は `max_payload_mb`（既定 8 MB、base64 後）。超えるとフレーム数を等間隔に減らす。
Artifact の上限 16 MB と、stdio の 1 メッセージとして運ぶ大きさの両方に対する余裕。

## 密度マップ

1. `mrcfile` で読み、ヘッダの `mapc` / `mapr` / `maps`（ファイルの列・行・断面がどの軸か）に従って
   `values[x, y, z]` に並べ替える
2. 最初のボクセルの位置は、ヘッダの `origin` が 0 でなければそれ、0 なら `nxstart` 等 × ボクセル幅
3. ブロック平均で間引く。平均したボクセルの位置は、元のボクセル群の中心（原点を `(f-1)/2` ボクセルずらす）
4. 構造は重心を原点に移して表示するので、マップの原点も同じだけ動かす
5. `uint8` に丸めて（値 = 最小値 + q × 幅）base64 で埋め込む。ビューアは 3Dmol.js の `VolumeData` に
   値を入れ、`addIsosurface` で描く（しきい値を変えるたびに作り直す）

軸の並びと原点の解釈を間違えるとエラーにならずにマップがずれるので、`atoms_inside_map` で確かめる。

## 周期境界の補正（結合情報なし）

MD の出力では分子が箱の境界で千切れている。結合情報が無いファイル（PDB + XTC など）でも動くように、
残基の連続性だけを使う:

1. 各残基を、その最初の原子を基準に最小像で繋ぎ直す（残基は箱の半分より小さい）
2. 連続する残基の重心どうしを最小像で並べ、ずれを累積して残基全体に適用する
3. 選択部分の重心を原点へ（並進の漂いを消す）
4. `align=True` なら CA 原子（3 個未満なら全原子）で最初のフレームに回転で重ねる

鎖が複数ある系では、鎖の末端と次の鎖の先頭も「連続する残基」として扱うので、鎖間の配置が最小像に寄る。
構造ファイル単体（軌道なし）では何もしない（結晶構造の配置を変えないため）。

## ビューア

3Dmol.js 2.5.5 を 1 ファイルに同梱し、ビルド工程を持たない。`viewer/core.js` が単体 HTML と MCP App の
両方で使う描画・コントロールのロジックで、`template.html`（ペイロードを埋め込む）と `app.html`
（ホストから postMessage で受け取る）が薄い殻。

- PDB は `keepH: true` で読む。3Dmol.js は既定で水素を捨てるので、そのままだと軌道の座標が原子に対してずれる
- フレームは `model.setCoordinates(座標, "array")` で載せ、`viewer.setFrame(i)` で切り替える
- 二次構造は最初のフレームの幾何から 3Dmol.js が決め、全フレームで同じ
- 表面とラベルは `setFrame` に追従しないので、フレームを替えるたびに作り直す。表面は重いので再生中は消し、
  同じフレームに 0.15 秒留まったら作る
- 原子クリック（`setClickable`）は `setCoordinates` より前に設定する。`setCoordinates` は原子をフレームごとに
  複製し、`setClickable` は今のフレームの原子にしか効かないため

## 実測（2026-10-30、floyd）

ATLAS の 1cvr_A（6662 原子、30003 フレーム、DCD 3 本 2.4 GB）で、サーバー側の処理時間と HTML の大きさ:

| 選択 | フレーム | 原子 | 抽出 | HTML |
|---|---|---|---|---|
| `protein`（水素込み） | 50 | 6662 | 1.3 秒 | 3.8 MB |
| `protein`（既定、水素なし） | 50 | 3363 | 0.1 秒 | 2.2 MB |
| `name CA` | 50 | 435 | 0.0 秒 | 0.8 MB |
| 水素なし | 200 | 3363 | 5.6 秒 | 6.2 MB |

ALA2（22 原子）は 250000 フレームから 100 フレームで 0.3 秒、0.57 MB。ブラウザ側の描画時間は未計測。

3C91（46578 原子）+ EMD-1733（144³ → 72³）の `view_density` は 1.6 秒、HTML 4.9 MB（2026-11-01）。
