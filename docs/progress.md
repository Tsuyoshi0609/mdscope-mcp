# 進捗

## 目標

floyd 上の構造ファイル・MD 軌道を、Claude Code / Codex のチャットから「見せて」で確認できる。

| 優先 | 目標 | 判定 |
|---|---|---|
| 1 必須 | 構造ファイルをインタラクティブに見る | 回転・ズームできる cartoon が手元の画面に出る |
| 2 必須 | MD 軌道をインタラクティブに見る | スライダーと再生。10 万原子・1 万フレームでも 1 分以内 |
| 3 できれば | 表現の変更 | sticks / spheres / surface、配色、ハイライト、部分ごとの重ね合わせ、ラベル |
| 4 余力 | 密度マップを静止構造に重ねる | `example/EMD-1733.map` が `example/3C91.pdb` を包み、しきい値をスライダーで動かせる |

## いま何をしているか（2026-11-01）

目標 1・2 は v0.1.0 として公開済み。目標 3 と、Codex で長いペイロードが切れる不具合の修正は push 済み。
目標 4（`view_density`）を実装しコミットした（未 push）。テスト 33 件が通る。
サーバー側では 3C91 + EMD-1733 で CA 原子の 97% が既定の等値面の内側に入る。

ブラウザでの確認待ち（node 上の 3Dmol.js でしか確かめていない）:

- 3C91 + EMD-1733（Artifact で公開済み、HTML 4.9 MB）: 等値面がモデルを包むか、スライダー・surface / mesh・
  不透明度・表示切替が効くか、46578 原子の cartoon と等値面で操作が重くないか
- AdK（`example/adenylate_kinase.*`）: 全体 cartoon + 残基 122〜159 の surface + 30〜59 の sticks + ラベル。
  再生・停止で表面が作り直されるか、2 段目の層の操作、原子クリックでのラベル、◐ での切替
- Codex / ChatGPT デスクトップの会話内ビューア（`ui://mdscope/viewer/v6.html`）で上の 2 つ。
  3C91 は約 5 MB を 24000 文字ずつ取り直すので、表示までの時間も見る

## 最大の問題

- 目標 2 の判定「10 万原子・1 万フレーム」級はサーバー側で未計測（floyd に該当データが無い）。
  `max_payload_mb=8` でフレーム数を自動で減らすので HTML は出るが、ブラウザ描画の重さは不明。
  surface はさらに重く、大きな系でどこまで実用になるかも不明。
- Codex の会話内ビューアは、大きなペイロードを小分けで取り直すため遅くなりうる（未計測）。
- Codex で表示までに 10 分近くかかった例がある。`AGENTS.md` とツール説明を直したが、効果は未確認。
