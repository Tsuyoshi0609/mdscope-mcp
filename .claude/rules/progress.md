# `docs/progress.md` の書き方

**進捗報告である。いま何をしていて、次に何をするかを、ここだけ読めば掴める状態に保つ。**
**過去の判断やその根拠は含まない。** 書き方全般は [document.md](document.md)（250 行上限もそちら）。

## 1. 書くこと（この 4 つだけ）

| 節 | 中身 |
|---|---|
| **目標** | 何ができれば成功か。判定基準つき |
| **いま何をしているか** | 走行中の計算（ログと出力の場所）、次に決めること、止まっている理由 |
| **最大の問題** | **一般公開するのに足りない機能**と、なぜ困るか。手法は書かない |
| **次にやること** | コマンド・設定・判断基準まで具体的に。細かい手順は `docs/local/todo.md` を指してよい |

**`docs/progress.md` だけを読んだ人が、現在の最大の問題を理解し、そのまま作業を続けられること。** 更新のたびに確かめる。

## 2. 書かないこと

- **過去の判断と、その根拠**（「〜だったので〜にした」）。
- **確定した実測値の一覧。**
- 本筋と関係ないこと（環境の不具合 → `help.md`、個別 run の詳細 → `docs/local/`）、途中経過の逐一、実測していない主張

## 3. 古い内容を積み重ねない（毎回）

**更新するたびに、全体を読み直して古くなった内容を片付ける。** 書き足すだけの更新をしない。

1. **終わったことは消す。** 「実行中」「次に〜する」が済んだら、その行を消す（済んだ印を付けて残さない）
2. **方針を変えたら、変更とその根拠を `docs/results/decisions.md` に書き、progress.md からは古い方針の記述を消す**
3. **撤回したら、 progress.md を黙って直す。**今後の判断・作業に影響するものだけ `docs/help.md` に残す
4. **目安は 120 行。** 超えていたら、上の 1〜3 のどれかが溜まっている

## 4. いつ直すか

- **作業の区切りで必ず直す。** 走らせっぱなしで放置しない
- 図や数値を `docs/` に書いたら、その出どころを同じコミットで `docs/results/` に残す
- 「いま何をしているか」に日時を書き、古い日時のまま残っていたら、まずそこを直す
