# `docs/local/` の使い方と整理

**`docs/local/` は git 追跡外の、気軽に使う置き場**（診断文書・軽いメモ・TODO）。論文にも現在の進捗の理解にも要らない内容を置く
（振り分けは [document.md](document.md) §1）。**最大 10 文書**。

**整理の起動条件: ユーザーが明示的に頼んだとき、または 10 文書を超えたとき。** それ以外は、自分の判断で消したり統合したりしない。

## 残す基準

**「いまの方針から見て、次に手を動かす人が読むべき知見」だけを残す。**

| 残す | 移す（`backup/`） |
|---|---|
| **示唆に富む検証結果** — 何が効かないと分かったか、どこに壁があるか | **現在の方針に関わらないもの** |
| **陥りやすい失敗** — 間違えるとエラーを出さずに結果が変わる経路 | **実装の詳細**（設計計画、コードの解説、キー一覧） |
| いまの方針の**根拠**になっている実測 | 個別 run の経過、採用しなかった案の長い検討 |

- **上限は 10 文書。少ないほどよい。** 超えるなら、内容を精査して統合するか落とす
- **古いファイルは `backup/docs/local_<YYYYMMDD>/` へ移す**（ユーザーが「削除して」と言ったときは削除してよい）
- 読めば分かる参照物（YAML のキー、保存物の読み方、スクリプトの引数）は `docs/local/` ではなく **`docs/code/`**（追跡する）に置く
- **追跡される文書から `docs/local/` を名指しするのは `docs/progress.md` → `docs/local/todo.md` だけにする**（clone した人には無いので）

## 手順

1. **一覧を作る。** ファイルごとに行数・更新日・**結論の数行**を読む（全文は読まない）
2. **残す構成を決め、ユーザーに何を移すか報告する**
3. `backup/docs/local_<YYYYMMDD>/` を作って移す
4. **残すファイルは書き直す。** 移したファイルから拾うべき知見を蒸留して入れ、
   **`docs/` に既に書いてあることは書かない**（同じ役割のファイルを 2 つ置かない）
5. **参照が切れていないか必ず確認する** ↓
6. 移したものと、残したファイルの中身をユーザーに報告する
